# Commit 記錄加密

「LoRA 個人化模型」區塊的「啟用加密記錄」預設關閉，右側顯示「密碼未設定」或「密碼已設定」。關閉時停止收集；已加密的記錄仍可輸入密碼後檢視或訓練。啟用狀態會保存，重啟後可只用公鑰繼續記錄。

首次勾選會開啟密碼設定視窗。視窗的 `Opened` 事件立即檢查應用程式訓練目錄 `runs` 下的 `training.jsonl` 與 `training.jsonl.partial`，發現就刪除並在視窗提示，不等待輸入密碼。無法檢查或刪除時停用確認按鈕。取消視窗不會復原已刪除的暫存檔。清理不會跟隨符號連結或 junction，也不刪除模型、adapter 等其他檔案。

密碼必須非空，首次設定需輸入兩次。設定成功時，SQLite 既有的明文 commit 欄位會在交易內轉為密文，並執行 `secure_delete`、`VACUUM`、WAL checkpoint。此流程不刪除既有 SQLite 記錄。檔案刪除與資料庫整理不保證消除 SSD、備份或作業系統先前留下的副本。

「檢視與選擇」和「開始訓練」每次都會要求密碼，兩者互不共用解鎖狀態。未提供密碼時，服務只回傳記錄 ID 與選擇用的中繼資料，不回傳對話內容。錯誤密碼、損毀密文、欄位移植與未加密記錄都不能進入解密訓練流程。

使用 libsodium 的 [Argon2id 密碼衍生](https://doc.libsodium.org/password_hashing/default_phf) 和 [X25519 sealed boxes](https://doc.libsodium.org/public-key_cryptography/sealed_boxes)。版本 1 固定使用 Argon2id13、3 次運算與 64 MiB 記憶體，由隨機 salt 和密碼產生 seed，再確定性產生加解密金鑰。SQLite 僅保存版本、salt、公鑰和啟用狀態，不保存密碼、seed 或私鑰。私鑰與 seed 的暫存緩衝區在操作結束時清除，密碼不會寫入設定、命令列或日誌。`0000` 可用但很容易被猜中，密碼遺失無法復原。

對話的 context、answer、padding_json、reading 各自加密，明文中綁定 event ID 與欄位名稱，避免密文被交換後仍通過驗證。時間、ID、訓練狀態和選擇中繼資料仍為明文。

加密與 SQLite 寫入由低優先序背景執行緒完成，只快取公鑰。推理執行緒不執行密碼衍生、加密或資料庫寫入。佇列上限為 256 筆；滿載時捨棄新記錄，避免累積影響輸入反應。

訓練密碼視窗開啟時也會清除之前遺留的訓練暫存檔。驗證密碼後，服務在記憶體解密所選資料，再建立本次訓練需要的數值 JSONL。這個檔案可還原為文字，因此視為明文暫存：訓練程序結束後立即刪除，例外與取消也會嘗試清除；程序被強制終止所留下的檔案於下次訓練密碼視窗開啟時清理。訓練中的檔案不能由另一個清理動作刪除。

驗證涵蓋預設停用、開關與重啟、密碼錯誤、無密碼讀取阻擋、密文隨機性、竄改及欄位交換、舊資料轉換、暫存刪除與刪除失敗。執行 `ctest --test-dir <build> -C Release -R '^training-data-writer$' --output-on-failure`。測試也會輸出四個各 1 KiB 欄位的平均加密耗時，這不等同於整體推理延遲量測。
